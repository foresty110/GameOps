# Interview Prep

> 코드/문서에 설계 결정의 "왜"를 녹일 때 읽는다.

면접에서 다음 질문을 받았을 때 답할 수 있도록 코드와 README를 준비한다.

## 예상 질문 & 답변 포인트

- **"왜 Redis를 썼나요?"**
  → 상품 목록 캐싱. 자주 읽고 변경은 어드민이 가끔. TTL과 무효화 전략 설명.

- **"동시에 같은 한정 상품을 100명이 구매하면?"**
  → 비관락 또는 Redis 분산락. 어디에 적용했는지 코드 지목.

- **"재화 지급 API를 두 번 호출하면?"**
  → 멱등키(`Idempotency-Key`) 처리. 키 + 운영자 ID로 중복 차단.

- **"테스트는 어디까지 짰나요?"**
  → Service 레이어 위주. 멱등성/제재/노출 기간 필터링은 통합 테스트. 커버리지 수치 제시.

- **"GM이 실수로 전체 유저에게 메일을 보내면?"**
  → `SUPER_ADMIN` 권한 제한 + 사유 입력 필수 + Audit Log + 발송 전 확인 모달.

- **"이걸 실서비스로 키우면 뭘 바꾸겠어요?"**
  → Kafka 도입 위치(메일 대량 발송), Sentry/모니터링, K8s 배포(EKS), 읽기 전용 리플리카.

- **"BI 지표는 어떻게 집계되나요?"**
  → 사전 집계 테이블(`daily_metric`). 실서비스라면 배치 잡 또는 ETL이 채우는 구조. 현재는 시드 데이터로 시뮬레이션.

- **"왜 Package by Feature인가요?"**
  → 도메인 응집도. 기능 추가/제거 시 한 패키지만 손대면 됨. Layer-first보다 변경 영향 범위가 작음.
